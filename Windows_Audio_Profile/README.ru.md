# Windows Audio Profile

[English](README.md) | [Русский](README.ru.md)

Экспортирует настройки звуковых endpoint'ов Windows в JSON, проверяет отредактированный профиль, применяет его и восстанавливает предыдущее состояние.

Утилита управляет зарегистрированными устройствами воспроизведения и записи. Она не устанавливает драйверы, не связывает Bluetooth-устройства и не отключает физические PnP-устройства.

## Требования

- Windows 10 или Windows 11
- 64-битный Windows PowerShell 5.1
- Подтверждение прав администратора для `Apply` и `Undo`

Внешние PowerShell-модули и установленный .NET SDK не нужны.

## Команды

Экспортировать все зарегистрированные endpoint'ы, включая отключенные и неподключенные:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Export-AudioProfile.ps1 `
  -OutputPath .\my-audio-profile.json
```

Проверить измененный профиль без изменений в Windows:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Test-AudioProfile.ps1 `
  -ProfilePath .\my-audio-profile.json
```

Показать план без повышения прав и создания backup:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Apply-AudioProfile.ps1 `
  -ProfilePath .\my-audio-profile.json -WhatIf -Json
```

Применить настройки. `Strict` откатывает изменения после ошибки; `BestEffort` сохраняет независимые успешные изменения и перечисляет остальные:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Apply-AudioProfile.ps1 `
  -ProfilePath .\my-audio-profile.json -ApplyMode Strict
```

Восстановить backup, указанный в результате `Apply`:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Undo-AudioProfile.ps1 `
  -BackupPath .\Backups\20260927-120000-1234abcd
```

Параметр `-Json` включает машиночитаемый вывод публичных команд. Код завершения `0` означает успех, `1` — ошибку, `2` — частичный результат `BestEffort`.

## Поведение профиля

Профиль использует patch-семантику: отсутствующее поле не меняется. `name` — редактируемое имя endpoint'а в первой строке классической панели «Звук». Имена драйвера и PnP-устройства не меняются.

`volume` принимает либо `percent`, либо `decibels`, а также независимое значение `muted`. `format` описывает число каналов, частоту, разрядность, кодирование и маску каналов. Иконки задаются ссылками на существующие `.ico`, DLL или EXE; файлы не копируются.

`enabled` меняет состояние endpoint'а из классической панели «Звук». Физическое PnP-устройство и Bluetooth-адаптер не отключаются.

Списки приоритетов идут от наименее к наиболее предпочтительному устройству. `allRoles` охватывает Console, Multimedia и Communications. Значение в `roles` заменяет порядок для отдельной роли. Если для потока указан приоритет, список должен содержать все подходящие endpoint'ы этого потока. Устройства с системным признаком `NeverSetAsDefaultEndpoint` исключаются. Проверка сверяет и сохраненные уровни, и фактическое устройство по умолчанию для каждой настроенной роли.

Смотри [audio-profile.example.json](audio-profile.example.json) и [audio-profile.schema.json](audio-profile.schema.json).

`Test` и `Apply` проверяют типы JSON-токенов до преобразования документа PowerShell. Строки вроде `"false"` или `"50"` отклоняются там, где требуется Boolean или число.

## Сопоставление устройств

Сначала используется текущий endpoint ID. Если Windows пересоздала endpoint, требуются минимум два экспортированных стабильных признака: например, PnP Container ID, Device Instance ID или Hardware ID. Отображаемые имена не используются как идентификаторы. Ноль или несколько совпадений считаются ошибкой. `required: false` следует задавать только тогда, когда отсутствие устройства допустимо как предупреждение.

Экспортированный профиль привязан к текущей установке Windows SHA-256-хешем MachineGuid. `-IgnoreMachineBinding` разрешает осознанный перенос, но не ослабляет сопоставление устройств.

## Повышение прав и backup

`Apply` и `Undo` запрашивают UAC только при наличии изменений. Профиль или backup привязывается по SHA-256 к снимку до UAC. Обычные свойства применяются через Core Audio. Точные уровни приоритета требуют кратковременной задачи планировщика от SYSTEM и токена службы Windows Modules Installer (`TrustedInstaller`). Код и данные приоритета копируются во временный каталог ProgramData с защищенным ACL и проверяются по SHA-256 перед привилегированным запуском. У helper'а есть конечный таймаут. После операции задача и staging-каталог удаляются, а временный запуск службы откатывается; постоянная служба или фоновый helper не устанавливаются.

Перед изменениями `Apply` проверяет, что каждое затрагиваемое свойство можно сохранить, затем записывает `state.json` в `Backups/<timestamp>-<id>`. Другой каталог задается через `-BackupRoot`. `Undo` восстанавливает и проверяет только конкретные поля и потоки приоритета, которых касался исходный профиль. Несовпадение после восстановления считается ошибкой.

## Ограничения

- Windows открывает аудиопоток только активного endpoint'а. Для изменения громкости утилита временно включает отключенный endpoint, затем возвращает требуемое конечное состояние. Физически недоступное Bluetooth-устройство все равно может отклонить операцию.
- Драйвер может отклонить или позднее заменить формат общего режима. Это характерно, например, для Alternative A2DP Driver. `Apply` перечитывает состояние и сообщает о расхождении, но не гарантирует сохранение формата после переподключения.
- Виртуальный endpoint с фиксированным диапазоном `0 dB..0 dB` не имеет осмысленной процентной регулировки.
- Поканальные уровни, Microphone Boost, эффекты драйверов, состояние PnP, установка драйверов и Bluetooth-связывание не входят в первую версию.
- Панель управления звуком может показывать закешированные имена и иконки до повторного открытия.
- Версия 1 — переносимая скриптовая утилита, а не подписанный установщик. Защищенный staging исключает изменение после начала повышения прав, но утилита не аутентифицирует исходные скрипты до запуска. Храни checkout в доверенном каталоге и проверяй обновления перед подтверждением UAC.

## Тесты

Обычный набор работает только на чтение и не требует повышения прав:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tests\Test-WindowsAudioProfile.ps1
```

`Tests\Test-ElevatedApply.ps1` — отдельный интеграционный тест. Запускай его из повышенного Windows PowerShell только когда допустимы временные изменения приоритетов и имени endpoint'а. Он проверяет защищенный staging, строгий rollback и сбой приоритета в BestEffort, сверяет реальное состояние после Apply и Undo, затем возвращает исходное состояние и проверяет очистку.
