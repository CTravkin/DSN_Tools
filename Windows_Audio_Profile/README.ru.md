# Windows Audio Profile

[DSN Tools](../README.ru.md) | [English](README.md) | Русский

Windows Audio Profile экспортирует зарегистрированные устройства воспроизведения и записи в JSON, проверяет осознанно отредактированный профиль, применяет его и умеет восстанавливать предыдущее состояние.

Это административная скриптовая утилита, а не панель управления звуком и не установщик. Предполагаемый сценарий: **экспортировать, отредактировать, проверить, посмотреть план, применить**. Не составляй идентификаторы устройств вручную, если не понимаешь правила сопоставления.

## Возможности

- экспорт активных, отключенных и неподключенных устройств воспроизведения и записи
- управление отображаемыми именами, иконками, видимостью, громкостью, mute и форматом общего режима
- сохранение и применение приоритета устройств по умолчанию для Console, Multimedia и Communications
- сопоставление пересозданных устройств по Windows Stable ID, когда он доступен, с консервативным резервным алгоритмом
- проверка типов JSON и согласованности профиля до изменений в Windows
- создание восстанавливаемого backup и проверка состояния после Apply и Undo
- обычный и машиночитаемый вывод со стабильными кодами завершения

Утилита не устанавливает драйверы, не связывает Bluetooth-устройства, не отключает физические PnP-устройства и не управляет эффектами драйверов.

## Стек

- 64-битный Windows PowerShell 5.1
- C#-interop с Core Audio, который PowerShell компилирует во время запуска
- JSON-профиль и [JSON Schema](audio-profile.schema.json)

Внешние PowerShell-модули и установленный .NET SDK не нужны.

## Платформы

Целевые платформы — x64 Windows 10 и Windows 11. Текущая реализация проверена на Windows 11 25H2, сборка 26200.9550. Другие сборки Windows и аудиодрайверы следует считать целевыми, но не проверенными сочетаниями.

[`StableId`](https://learn.microsoft.com/en-us/windows/win32/coreaudio/pkey-audioendpoint-stableid) доступен начиная с Windows 11 24H2. Он экспортируется, только если Windows предоставляет его для устройства. Без него профиль использует более строгий старый fingerprint.

Хранилище приоритетов и часть свойств устройств относятся к внутренней реализации Windows, а не к полноценному публичному API администрирования. После переноса утилиты на другую сборку Windows или компьютер всегда запускай `Test` и `-WhatIf`.

## Требования

- доверенный локальный checkout репозитория
- 64-битный `powershell.exe`
- подтверждение UAC для Apply и Undo, когда нужны изменения
- уже существующие на целевом компьютере файлы и ресурсы иконок

Запускай команды из каталога `Windows_Audio_Profile`.

## Обмен данными

### JSON-профиль

Начинай с экспорта текущего компьютера. Не изменяй сгенерированные поля в `target` и `match`: они идентифицируют установку Windows и ее устройства. Редактируй `profile`, `required`, `settings` и `priority`.

Профиль использует patch-семантику: отсутствующая настройка остается без изменений. Например, этот фрагмент меняет только имя, громкость, mute и формат:

```json
"settings": {
  "name": "Studio microphone",
  "volume": {
    "percent": 80,
    "muted": false
  },
  "format": {
    "channels": 1,
    "sampleRateHz": 48000,
    "bitsPerSample": 24,
    "encoding": "pcm"
  }
}
```

Основные поля:

- `name` — имя устройства в первой строке классической панели «Звук»; имена драйвера и PnP-устройства не меняются
- `icon` ссылается на существующий `.ico`, DLL или EXE; утилита не копирует файл
- `enabled` управляет видимостью устройства в классической панели «Звук», а не физическим устройством
- `volume` принимает либо `percent`, либо `decibels`, а также независимое значение `muted`
- `format` задает число каналов, частоту, разрядность, кодирование и необязательную маску каналов общего режима
- `required: false` превращает отсутствие устройства из ошибки в предупреждение

Списки приоритетов идут от наименее к наиболее предпочтительному устройству:

```json
"leastToMostPreferred": [
  "monitor",
  "speakers",
  "headphones"
]
```

`allRoles` применяет один порядок для Console, Multimedia и Communications. Значения в `roles` заменяют его для отдельной роли. Если приоритет задан для потока воспроизведения или записи, список должен содержать все подходящие устройства этого потока. Устройства с системным признаком `NeverSetAsDefaultEndpoint` исключаются.

Используй [audio-profile.example.json](audio-profile.example.json) как пример структуры, а [audio-profile.schema.json](audio-profile.schema.json) — для проверки в редакторе. В примере стоят фиктивные идентификаторы; применять его напрямую нельзя.

### Сопоставление устройств

Сопоставление останавливается при любой неоднозначности и идет в таком порядке:

1. точный endpoint ID вместе с экспортированным fingerprint
2. точный, регистрозависимый `StableId`, если он есть
3. минимум два совпадающих старых признака, например PnP Container ID, Device Instance ID или Hardware ID

Отображаемые имена никогда не служат идентификаторами. Ноль или несколько кандидатов считаются ошибкой. `StableId` — непрозрачное значение Windows: не нормализуй его, не меняй регистр и не пытайся составить вручную.

Профиль привязан к исходной установке Windows SHA-256-хешем `MachineGuid`. `-IgnoreMachineBinding` разрешает осознанный перенос, но не ослабляет сопоставление устройств.

## Работа с утилитой

### 1. Экспорт

Экспортируй все зарегистрированные устройства, включая отключенные и неподключенные:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Export-AudioProfile.ps1 `
  -OutputPath .\my-audio-profile.json
```

Сохрани исходный экспорт до успешного применения и проверки измененного профиля.

### 2. Редактирование

Оставь в профиле только те настройки и приоритеты, которыми нужно управлять. Если настройку не нужно фиксировать, удали ее из `settings` вместо копирования текущего значения.

Не переименовывай и не переставляй ключи устройств после того, как сослался на них в `priority`. Не заменяй сгенерированные идентификаторы отображаемыми именами.

### 3. Проверка

Проверь документ и сопоставь устройства без изменений в Windows:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Test-AudioProfile.ps1 `
  -ProfilePath .\my-audio-profile.json
```

`Test` и `Apply` проверяют исходные типы JSON до преобразования PowerShell. Значения вроде `"false"` и `"50"` отклоняются там, где нужны Boolean и число.

### 4. Предпросмотр

Посмотри точный план применения без повышения прав и создания backup:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Apply-AudioProfile.ps1 `
  -ProfilePath .\my-audio-profile.json -WhatIf
```

Добавь `-Json`, если результат будет читать другая программа.

### 5. Применение

Для ручного запуска начинай со `Strict`. При ошибке он откатывает профиль:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Apply-AudioProfile.ps1 `
  -ProfilePath .\my-audio-profile.json -ApplyMode Strict
```

`BestEffort` сохраняет независимые успешные изменения и сообщает об остальных. Используй его, только если допустим частичный результат.

### 6. Отмена

Apply сообщает путь созданного backup. Восстанови его командой:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Undo-AudioProfile.ps1 `
  -BackupPath .\Backups\20260927-120000-1234abcd
```

Undo восстанавливает и проверяет только поля и потоки приоритета, которых касался исходный профиль.

### Вывод и коды завершения

Добавь `-Json` к любой публичной команде для машиночитаемого результата.

- `0` — успех
- `1` — ошибка
- `2` — частичный результат `BestEffort`

### Повышение прав, backup и восстановление

Apply и Undo запрашивают UAC только при наличии изменений. До Apply каждое затрагиваемое свойство должно читаться для backup. По умолчанию backup создается в `Backups/<timestamp>-<id>/state.json`; другой каталог задается через `-BackupRoot`.

Обычные свойства применяются через Core Audio. Точные уровни приоритета требуют кратковременной задачи планировщика от SYSTEM и токена процесса службы Windows Modules Installer (`TrustedInstaller`). Код и данные копируются во временный каталог ProgramData с защищенным ACL и проверяются по SHA-256 перед привилегированным запуском. У helper есть конечный таймаут. После операции задача и staging-каталог удаляются, а временный запуск службы откатывается; постоянная служба или фоновый процесс не устанавливаются.

Профиль или backup привязывается по SHA-256 к снимку, сделанному до UAC. Несовпадение после восстановления считается ошибкой.

## Ограничения

- Windows открывает аудиопоток только активного устройства. Для изменения громкости утилита может временно включить отключенное устройство, а затем вернуть требуемое конечное состояние. Физически недоступное Bluetooth-устройство все равно может отклонить операцию.
- Драйвер может отклонить или позднее заменить формат общего режима. Это характерно, например, для Alternative A2DP Driver. Apply перечитывает состояние, но не гарантирует сохранение формата после переподключения.
- Виртуальный endpoint с фиксированным диапазоном `0 dB..0 dB` не имеет осмысленной процентной регулировки.
- Поканальные уровни, Microphone Boost, эффекты драйверов, физическое состояние PnP, установка драйверов и Bluetooth-связывание не входят в первую версию.
- Панели управления звуком могут показывать закешированные имена и иконки до повторного открытия.
- Это неподписанная скриптовая утилита. Защищенный staging исключает изменение привилегированного кода после попадания в staging, но не аутентифицирует сам checkout. Проверяй обновления и храни репозиторий в доверенном каталоге до подтверждения UAC.

## Проверка разработки

Обычный набор работает только на чтение и не требует повышения прав:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tests\Test-WindowsAudioProfile.ps1
```

`Tests\Test-ElevatedApply.ps1` — отдельный интеграционный тест. Запускай его из повышенного Windows PowerShell, только когда допустимы временные изменения приоритетов и имени устройства. Он проверяет защищенный staging, строгий rollback, сбой приоритета в BestEffort, фактическое состояние после Apply и Undo, восстановление исходного состояния и очистку.
