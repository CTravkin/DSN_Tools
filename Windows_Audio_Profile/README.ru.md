# Windows Audio Profile

[English](README.md) | [Русский](README.ru.md) | [DSN Tools](../README.ru.md)

Windows Audio Profile — административная утилита для экспорта, проверки, применения и отката настроек устройств воспроизведения и записи Windows через явный JSON-профиль.

Она управляет зарегистрированными аудиоустройствами, а не физическим оборудованием. Установка драйверов, связывание Bluetooth, состояние PnP, поканальные уровни, Microphone Boost и эффекты драйверов не входят в ее задачу.

## Функции

- экспорт активных, отключенных и неподключенных устройств воспроизведения и записи
- управление отображаемыми именами, иконками, видимостью, громкостью, mute и форматом общего режима
- применение приоритета устройств по умолчанию для Console, Multimedia и Communications
- сопоставление пересозданных устройств по Windows Stable ID или консервативному старому fingerprint
- проверка и предпросмотр профиля до изменений, затем backup, верификация, rollback или восстановление затронутого состояния
- обычный и машиночитаемый вывод со стабильными кодами завершения

## Стек

- 64-битный Windows PowerShell 5.1
- C#-interop с Core Audio, компилируемый во время запуска
- JSON-профиль, проверяемый по [JSON Schema](audio-profile.schema.json)

Внешние PowerShell-модули и установленный .NET SDK не нужны.

## Платформы

Целевые платформы — x64 Windows 10 и Windows 11. Текущая версия проверена на Windows 11 25H2, сборка 26200.9550; другие сборки Windows и аудиодрайверы считаются целевыми, но не проверенными сочетаниями.

`PKEY_AudioEndpoint_StableId` появился в Windows 11 24H2. Он гарантирован не для каждого устройства, поэтому утилита сохраняет более строгий старый алгоритм сопоставления. Приоритет устройств по умолчанию и часть их свойств зависят от внутренней реализации Windows; после смены сборки Windows, драйверов или оборудования заново проверяй профиль и план применения.

## Требования

- доверенный локальный checkout
- 64-битный `powershell.exe`
- подтверждение UAC, когда Apply или Undo требуют изменений
- уже существующие локальные файлы или ресурсы для настроенных иконок

Запускай команды из каталога `Windows_Audio_Profile`.

## Обмен данными

Утилита читает и записывает версионированный JSON-профиль. Экспортируй профиль на целевом компьютере и редактируй этот файл; не составляй идентификаторы устройств вручную.

| Раздел | Назначение |
|---|---|
| `target` | Идентифицирует исходную установку Windows |
| `devices[].match` | Содержит сгенерированные идентификаторы устройств; обычно эти значения не изменяются |
| `devices[].settings` | Выбирает управляемые имя, иконку, видимость, громкость, mute и формат |
| `priority` | Располагает подходящие устройства воспроизведения и записи от наименее к наиболее предпочтительному |

Профиль использует patch-семантику: отсутствующая настройка остается без изменений. Указывай `required: false`, только если отсутствие устройства должно давать предупреждение вместо ошибки.

Сопоставление останавливается при любой неоднозначности:

1. точный endpoint ID и экспортированный fingerprint
2. точный регистрозависимый `StableId`, если он доступен
3. минимум два совпадающих старых признака, например Container ID, Device Instance ID или Hardware ID

Отображаемые имена никогда не служат идентификаторами. Ноль или несколько совпадений считаются ошибкой. Профиль привязан к исходной установке SHA-256-хешем `MachineGuid`; `-IgnoreMachineBinding` разрешает осознанный перенос, но не ослабляет сопоставление устройств.

Полная структура приведена в [примере профиля](audio-profile.example.json). Его идентификаторы фиктивны, поэтому применять пример напрямую нельзя.

## Эксплуатация

### Использование

1. Экспортируй текущий список устройств:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Export-AudioProfile.ps1 `
     -OutputPath .\my-audio-profile.json
   ```

2. Редактируй только `settings`, `required`, метаданные профиля и `priority`. Удали настройки, которыми профиль не должен управлять. Сохрани исходный экспорт до успешного применения и проверки измененного профиля.

3. Проверь сопоставление устройств и посмотри план без изменений в Windows:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Test-AudioProfile.ps1 `
     -ProfilePath .\my-audio-profile.json

   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Apply-AudioProfile.ps1 `
     -ProfilePath .\my-audio-profile.json -WhatIf
   ```

4. Примени профиль в режиме `Strict` с автоматическим откатом после ошибки:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Apply-AudioProfile.ps1 `
     -ProfilePath .\my-audio-profile.json -ApplyMode Strict
   ```

   `BestEffort` сохраняет независимые успешные изменения и возвращает частичный результат. Используй его, только если частичное применение допустимо.

5. Apply сообщает путь созданного backup. Восстанови это состояние командой:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Undo-AudioProfile.ps1 `
     -BackupPath .\Backups\20260927-120000-1234abcd
   ```

Добавь `-Json` к публичной команде для машиночитаемого вывода. Коды завершения: `0` — успех, `1` — ошибка, `2` — частичный результат `BestEffort`.

Apply и Undo запрашивают UAC только при наличии изменений. До Apply утилита проверяет возможность сохранить затрагиваемые значения и по умолчанию записывает `state.json` в `Backups/<timestamp>-<id>`. Точные изменения приоритета выполняет кратковременный защищенный helper от SYSTEM и `TrustedInstaller`; после операции удаляются его задача планировщика и staging-каталог, а временный запуск службы откатывается.

Эксплуатационные ограничения:

- физически недоступное Bluetooth-устройство может отклонить изменение громкости
- драйвер может отклонить или позднее заменить формат общего режима, в том числе после переподключения через альтернативный A2DP-драйвер
- виртуальные устройства с фиксированным диапазоном `0 dB..0 dB` не имеют осмысленной процентной регулировки
- панели управления звуком могут показывать закешированные имена и иконки до повторного открытия
- скрипты не подписаны; проверяй обновления и храни checkout в доверенном каталоге до подтверждения UAC

### Проверка

Обычный набор работает только на чтение и не требует повышения прав:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tests\Test-WindowsAudioProfile.ps1
```

`Tests\Test-ElevatedApply.ps1` — отдельный интеграционный тест. Запускай его только из повышенного Windows PowerShell, когда допустимы временные изменения имени устройства и приоритета. Тест возвращает исходное состояние и проверяет очистку.
